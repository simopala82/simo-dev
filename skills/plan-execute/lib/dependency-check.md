# Dependency freshness check

Loaded on demand from `plan-execute` `SKILL.md` step 1 when `plan_execute_preflight.py` prints a `depends-on:` line other than `none` (the plan header's `Depends on: <TICKET>` field). Run it before creating any todos — a stale worktree that still compiles is not proof the dependency is unchanged (incident 2026-08-05: a blocking sub-task merged with a different API shape than the plan assumed, and the worktree kept building because no touched symbol had been removed). `depends-on: unparsed: <text>` → read the key from the plan header; none there → ask the user which ticket the plan depends on.

```bash
R="${CLAUDE_PLUGIN_ROOT}"; [ -d "$R" ] || R="$HOME/.claude/local-marketplace/simo-dev"; [ -d "$R" ] || R="$(find -H "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/cache" -mindepth 3 -maxdepth 3 -type d 2>/dev/null | grep "/simo-dev/[^/]*$" | sort -V | tail -1)"
python3 "$R/lib/check_dependency_ticket.py" <TICKET> --repo "<worktree-abs>" --base "<base>"
```

`<base>` (`SKILL.md` step 1 **Preflight**) unknown → drop `--base` (the script falls back to the remote default branch, and a dependency merged into a different integration branch then reads as `open`). A `<base>` with no `origin/<base>` ref prints `unverifiable`, never a silent `open`.

- `open` → the ticket is not Done and no commit naming it is on `origin/<base>` → proceed normally; the dependency isn't ready yet, nothing to re-verify.
- `resolved-with-diff` → whenever a commit naming the key is on the base, the printed diff is that commit's, whatever the status; for a ticket not yet Done this is also what makes it resolved (a `status: <X> (merged into <base>)` line precedes the diff, for that case only). That commit is a signal, not proof of the merge, and its diff can be partial (several MRs, a rebase-merge, a hit on one branch-side commit of a merge whose own message omits the key, a later follow-up, a revert or another commit that only mentions the key being the newest hit), so the confirmation below still applies. A Done ticket with no such commit gets its diff from branch/log/forge lookups, which can pick unmerged work. Show the printed diff next to the plan's `assumed shape`. Ask the user to confirm the diff still matches the assumption before continuing. On a mismatch, stop — instead of executing against a stale assumption, mark the plan superseded and re-run `simo-dev:task-intake` on the same ticket or prompt with the printed diff as context (`deep-dive` at its step 4 for a design-level mismatch): it writes a new plan through its writer subagent and gate.
- `resolved-no-diff-found` / `unverifiable` (without an `(origin/<base> not found)` line — that case is the next bullet) → the dependency looks resolved (or its status could not be read) but its shape could not be recovered automatically. Warn and ask for manual confirmation before continuing — never block silently, never assume a match. For a ticket not yet Done, `resolved-no-diff-found` is followed by the same `status: <X> (merged into <base>)` line.
- `unverifiable` + `status: <X> (origin/<base> not found)` → a different case: the ticket is not Done and the merge check could not run, because `origin/<base>` does not resolve. The dependency may still be open. Check the `--base` value and that an `origin` remote exists, re-run, and only then ask.
