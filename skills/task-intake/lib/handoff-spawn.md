**spawn_task fields:**

- `title`: `Implement <jira-key-or-short-desc>` (≤60 chars, imperative)
- `tldr`: `Execute the implementation plan for <task gist> in an isolated session (context isolation).`
- `cwd`: the **repo root absolute path** — never omit it and never a subdirectory. Omitted, it inherits this session's cwd, which after a step-6 adoption IS a worktree, so the harness puts the child's worktree at `<this-worktree>/.claude/worktrees/<random>` — inside the directory `mr-followup` step 8 removes when THIS task merges, taking the child's branch and any uncommitted work with it. Step 6 does now see it — nested worktrees share the main `.git`, so `<REAL>` is the main checkout and the path carries a `/.claude/worktrees/` segment, which is the move row. But a handoff spawn is the **same** task, so the move destination `<REAL>/.worktrees/<name>` is the parent's own worktree: the destination-exists guard stops and asks. Recovery is a question, not a fix, and it only runs if the child reaches step 6 at all — the `cwd` pin is what stops the shape happening (CLAUDE.md spawn-`cwd` rule).
- **`spawn_task` has no way to target an existing worktree** — its only fields are `title`, `tldr`, `cwd`, `prompt` (checked 2026-08-26 against the tool schema and against `skills/spawn-task/SKILL.md`, which documents `cwd` guidance only — the schema lives outside this repo and can change without this bullet being touched). Every call derives a **fresh** worktree from `cwd`, even when `cwd` is correctly the repo root: it never reuses a worktree this session already prepared manually (step 6 already run, plan and branch ready). If that's the case, do NOT use `spawn_task` for hand-off — it produces a second, disconnected worktree and the prepared one goes to waste. Use in-session execution with worktree discipline instead (the "In-session worktree" row of `SKILL.md` step 8's hand-off table). Observed on `refactor/mr-review-tracker-scope-fetch` (MR !181): the `spawn_task` result text said "start it in a fresh worktree with one click", confirming the already-prepared worktree would have been ignored — caught with `dismiss_task` before the chip was clicked.
- `prompt`: self-contained handoff — include all of:
  - absolute path to the plan file
  - worktree absolute path and branch name
  - ticket key (if any) and 1-line task gist
  - explicit instruction: "Worktree discipline: use `git -C \"<worktree-abs>\"` for every git op and absolute worktree paths for scripts/tests. Do NOT assume the Bash cwd is the worktree and do NOT `cd` to establish context — the Bash cwd is unreliable in both directions (it can survive several calls, and can be silently re-anchored)."
  - explicit instruction: "Read the plan, then proceed via `simo-dev:plan-execute`. Do NOT re-run intake/grilling — the plan is final (user already approved it via the plan review gate)."
  - explicit instruction: "Default to `simo-dev:tdd` for feature/fix work. Skip TDD only if the plan explicitly says so."
  - explicit instruction: "If any test goes red unexpectedly, switch to `simo-dev:debug` before touching code."
  - explicit instruction: "When implementation is complete, run `simo-dev:review-loop` (gates on `simo-dev:verify-done`, so make sure tests/build are green locally first)."
