## The check: evidence and limits

Read when a session working in this tree was missed, or the check stopped a tree this session owns. Evidence: the app sets `worktreePath` on the session it created the tree for; a session that inherited the folder has none, and its `originCwd` is the tree itself (observed 2026-11-09: 4 owners vs 1 inheriting child); after archiving an owner the app can reuse its tree for a new session, and the archived one loses the field (observed, 3 trees). Limits: a session on the same folder outside this session's linked family is not seen when this session owns the tree — one opened by hand, and possibly a child moved to top level (`detached` in `get_session`; an observed set, not a closed one) — the hand-off children this flow starts are no blind spot, since they stay linked (`lib/handoff-spawn.md` **Keep the child linked**) and `list_sessions` `linked: true` sees them; only a detach done by hand from the sidebar is not covered; row 3b trees are not checked (no owner field to read, never observed shared); the "started from another session" system-prompt line is not a signal — a child with its own worktree carries it too.
